# دفترچهٔ علمی من 📓

دفترچهٔ شخصی یادگیری دندان‌پزشکی — کاملاً فارسی و راست‌به‌چپ.

**فلسفه:** این سایت ابزار یادگیری است، نه تبلیغ. شواهد علمی از برداشت شخصی
جدا می‌شوند؛ نیمه‌کاره‌بودن و پرسیدن مجاز است؛ تغییر نظرات ثبت می‌شود.

---

## ۱) اجرای سایت — ساده‌ترین راه ⭐

**فایل `start-site.bat` را دوبار کلیک کنید.** دو پنجره باز می‌شود:
سایت روی `http://localhost:4321` و ناظر کشویی.

روش دستی (دو پنجرهٔ cmd در پوشهٔ پروژه):

```
npm run dev      ← پنجرهٔ اول: سایت
npm run inbox    ← پنجرهٔ دوم: ناظر کشویی
```

توقف: بستن پنجره‌ها یا `Ctrl+C`.

## ۲) افزودن مطلب بدون باز کردن این برنامه — «کشویی» 📥

فایل را در یکی از پوشه‌های `inbox` بیندازید؛ ناظر آن را خودکار به یادداشت
سایت تبدیل می‌کند (متن Word استخراج می‌شود، فرانت‌متر ساخته می‌شود):

| بیندازید در | می‌رود به |
| --- | --- |
| `inbox/everyone/` | بخش «برای همه» |
| `inbox/professionals/` | بخش «برای دندان‌پزشکان» |
| `inbox/failsafe/` | پروژهٔ Failuresafe |
| `inbox/abrz/` | پروژهٔ ABRZ |
| `inbox/notebook/` | دفترچهٔ یادگیری |

قواعد:
- **Word (.docx) و متن (.txt/.md):** پاراگراف اول (یا خط `# ...`) می‌شود عنوان.
- **PDF:** به‌صورت *پیش‌نویس* (`draft: true`) اضافه می‌شود تا بعد از خواندن، خودتان کاملش کنید.
- فایل اصلی حذف نمی‌شود؛ به `inbox/_processed/` منتقل می‌شود.
- بعد از هر افزودن، صفحهٔ سایت خودش تازه می‌شود (چند ثانیه صبر کنید).
- عنوان را می‌توانید بعداً در فایل ساخته‌شده در `src/content/...` ویرایش کنید.
- **نشانی اینترنتی (URL):** اگر نام فایل را انگلیسی بنویسید (مثلاً `white-spot.md`)، نشانی تمیز می‌گیرد (`/everyone/white-spot`)؛ نام فارسی → نشانی زمان‌دار (`note-2026…`). عنوان نمایش‌داده‌شده در هر دو حالت همان متن شماست.
- ناظر فقط وقتی فعال است که `start-site.bat` (یا `npm run inbox`) در حال اجرا باشد.

### میان‌بر: پوشهٔ مواد پژوهشی هم زیر نظر است 📁

فایل **Word/متن** را می‌توانید مستقیم در پوشه‌های مواد خودتان هم بگذارید؛ ناظر آن را
**کپی** می‌کند به بخش مربوطه (فایل اصلی سر جایش می‌ماند):

| این پوشه | می‌رود به |
| --- | --- |
| `برای دندانپزشکان/projects/ABRZ/` | پروژهٔ ABRZ |
| `برای دندانپزشکان/projects/failsafe/` | پروژهٔ Failuresafe |
| `برای دندانپزشکان/` | بخش «برای دندان‌پزشکان» |
| `برای همه/` | بخش «برای همه» |

فایل‌های **PDF خامِ مقاله‌ها** در پوشهٔ مواد نادیده گرفته می‌شوند (مادهٔ مطالعه‌اند، نه محتوای سایت)؛
برای انتشار یادداشتشان، از inbox استفاده کنید. تغییر فایل → به‌روزرسانی خودکار یادداشت در سایت.

## ۳) بخش‌های سایت

| بخش | پوشهٔ محتوا | نشانی |

## ۴) نوشتن/ویرایش مستقیم یادداشت

قالب هر فایل در `src/content/...`:

```
---
title: عنوان
description: خلاصهٔ یک‌خطی
pubDate: 2026-11-09
kind: reading-note   ← اختیاری: reading-note / question / lesson / reflection / idea / article
paper: (نقل کامل مقالهٔ مرجع)   ← برای یادداشت مطالعه
updated: 2026-12-01  ← اختیاری؛ تاریخ آخرین بازنگری
changelog:           ← اختیاری؛ سابقهٔ تغییرات فکری
  - date: 2026-12-01
    note: چه چیزی عوض شد و چرا
---

متن...
```

قانون‌های مهم:
- بخش بالای فایل (بین دو `---`) همیشه اولین چیز فایل باشد.
- عنوان دارای «:» داخل گیومه: `title: 'حساسیت دندان: چه کنیم؟'`
- منتشرنشدن موقت: `draft: true`

### بلوک‌های «صداقت»

```
:::evidence
یافتهٔ مستند از مقالهٔ منتشرشده، با ارجاع.
:::

:::interpretation
برداشت و تفسیر شخصی من.
:::

:::experience
تجربهٔ بالینی خودم.
:::

:::hypothesis
فرضیه یا پرسش بررسی‌نشده — نه ادعا.
:::
```

## ۵) انتشار سایت در اینترنت (وقتی خواستید) 🌐

فعلاً سایت لوکال است. برای انتشار، سه گام:

1. در `astro.config.mjs` مقدار `site` را به نشانی واقعی (مثلاً
   `https://daftarche.netlify.app`) تغییر دهید.
2. دستور `npm run build` را بزنید؛ خروجی در پوشهٔ `dist/` ساخته می‌شود.
3. پوشهٔ `dist` را در یکی از سرویس‌های رایگان بگذارید:
   - **Netlify Drop** — ساده‌ترین: در سایت app.netlify.com/drop پوشهٔ dist را بکشید و رها کنید.
   - **Vercel / GitHub Pages** — برای اتصال مستقیم به این پوشهٔ پروژه.

هر وقت خواستید، بگویید تا قدم‌به‌قدم همراهتان بروم.

## ۶) تغییرات رایج

| می‌خواهم… | کجا |
| --- | --- |
| نام سایت را عوض کنم | `src/config.ts` → `name` |
| اطلاعات پروفایل (تلفن، نشانی، اینستاگرام) | `src/config.ts` → `author` |
| رنگ اصلی سایت را عوض کنم | `src/styles/global.css` → `--accent` |

## ۷) نسخه‌پشتیبان (git)

هر تغییر خوب: `git add .` و `git commit -m "توضیح"`. تاریخچهٔ کامل فکری‌تان
همین‌جا روی کامپیوتر خودتان می‌ماند.
